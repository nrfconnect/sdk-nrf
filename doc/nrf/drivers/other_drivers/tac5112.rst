.. _lib_tac5112:

TAC5112 audio codec driver
##########################

.. contents::
   :local:
   :depth: 2

The TAC5112 driver lets you configure and operate the Texas Instruments TAC5112 low-power stereo audio codec.
The TAC5112 provides a 105 dB dynamic-range stereo ADC and a 114 dB dynamic-range stereo DAC, with a programmable low-jitter PLL, digital volume control, and battery and thermal fault protection.
See `TAC5112 product page`_ for more information about the device.

The driver controls the codec over I2C and conforms to the :ref:`Zephyr audio codec API <zephyr:audio_codec_api>`.
Audio sample data is carried separately over the codec's audio serial interface (I2S or left-justified).

Supported features
******************

The driver implements the following members of the Zephyr audio codec API:

* Codec configuration (``audio_codec_configure``): software reset, sleep exit, audio serial interface format (I2S or left-justified) and word length (16, 20, 24, or 32 bits), and automatic PLL and clock configuration. The ``dai_route`` field selects the paths used: ``AUDIO_ROUTE_PLAYBACK`` enables only the ``output-channels``, ``AUDIO_ROUTE_CAPTURE`` only the ``input-channels``, and ``AUDIO_ROUTE_PLAYBACK_CAPTURE`` both. ``AUDIO_ROUTE_BYPASS`` and unknown values are rejected with ``-ENOTSUP``.
* Output enable and disable (``audio_codec_start_output`` / ``audio_codec_stop_output``) and direction-selectable power control (``audio_codec_start`` / ``audio_codec_stop``).
* Per-channel output and input digital volume in 0.5 dB steps, and mute (``audio_codec_set_property`` / ``audio_codec_apply_properties``).
* Fault reporting (``audio_codec_clear_errors`` / ``audio_codec_register_error_callback``): output short-circuit and virtual-ground faults are delivered to a registered callback through the optional codec interrupt line.
* Record and playback channel selection: the enabled ADC input and DAC output channels are chosen with the ``input-channels`` and ``output-channels`` devicetree properties and can be re-selected at runtime with ``tac5112_set_channels()``.
* Clock configuration: automatic PLL and clock setup for standard audio rates, explicit PLL and divider programming for ratios outside the auto-detection table, and fine runtime trimming of the PLL sample rate for clock recovery.

In addition, the driver exposes helpers for explicit PLL and clock-divider configuration (``tac5112_configure_pll()``) and fine PLL sample-rate trimming (``tac5112_trim_pll()``); see `Clock configuration and recovery`_.

Configuration
*************

To enable the driver, set the :kconfig:option:`CONFIG_AUDIO_TAC5112` Kconfig option.
This option depends on :kconfig:option:`CONFIG_AUDIO` and :kconfig:option:`CONFIG_AUDIO_CODEC`, and selects :kconfig:option:`CONFIG_I2C`.

The following Kconfig options are available:

* :kconfig:option:`CONFIG_AUDIO_TAC5112` - Enables the TAC5112 codec driver.
* :kconfig:option:`CONFIG_AUDIO_TAC5112_EMUL` - Enables the I2C emulator used to run the driver's tests without hardware. Intended for test builds only.

Devicetree
==========

The codec node must be a child of an I2C controller node and use the ``ti,tac5112`` compatible (:dtcompatible:`ti,tac5112`).
Set the ``reg`` property to the 7-bit I2C address selected by the codec ``ADDR`` pin (``0x50`` to ``0x53``).

The following optional properties are supported:

* ``reset-gpios`` - Hardware reset line, driven inactive during initialization to release the codec from reset.
* ``fault-gpios`` - GPIO connected to the codec ``GPIO1`` pin, which is the interrupt output out of reset.
  The driver does not configure any other pin as the interrupt output.
  When present, the driver services the interrupt from the system workqueue and invokes the callback registered with ``audio_codec_register_error_callback``. Without it, asynchronous fault reporting is unavailable. ``audio_codec_clear_errors`` only clears the latched fault registers and does not return the fault status.
* ``input-channels`` - Bitmask of ADC record channels enabled at configure time, where bit 0 is channel 1 and bit 1 is channel 2 (valid range ``0x0`` to ``0x3``). The default ``0x3`` enables both stereo channels. When any input channel is enabled the driver also powers the ADC and MICBIAS.
* ``output-channels`` - Bitmask of DAC playback channels enabled at configure time, with the same encoding and range. The DAC itself is powered on ``audio_codec_start_output()``.

The following snippet shows an example configuration:

.. code-block:: devicetree

   &i2c1 {
           status = "okay";
           tac5112: audio-codec@50 {
                   compatible = "ti,tac5112";
                   reg = <0x50>;
                   reset-gpios = <&gpio1 8 GPIO_ACTIVE_LOW>;
                   fault-gpios = <&gpio0 19 GPIO_ACTIVE_LOW>;
                   input-channels = <0x3>;
                   output-channels = <0x3>;
           };
   };

Clock configuration and recovery
********************************

By default the driver runs the codec's automatic clock configuration: ``audio_codec_configure()`` observes the incoming BCLK/FSYNC ratio and derives the PLL and clock dividers for the requested sample rate.
This suits the common setup where the codec is the audio-serial-interface target and the host (for example, the nRF I2S peripheral) generates BCLK and FSYNC.

.. note::
   ``audio_codec_configure()`` always reprograms automatic PLL mode.
   This resets any custom PLL configuration applied earlier with ``tac5112_configure_pll()`` and disables runtime trimming until a new custom PLL is programmed.
   Apply a custom PLL, or set up clock recovery, after calling ``audio_codec_configure()``.

For clock ratios outside the auto-detection table, ``tac5112_configure_pll()`` programs the raw PLL and divider registers (custom mode), including the fractional multiplier ``JMUL.DMUL``.

Clock recovery
==============

When the codec is the audio-serial-interface controller, its PLL sets the true audio sample rate for the system.
An application that has both a target render time and the actual render time for a block of samples can null the accumulating error by steering the codec clock, using ``tac5112_trim_pll()`` as the actuator of a software clock-recovery loop:

* Program a custom-mode PLL with ``tac5112_configure_pll()``.
  Choose a nominal ``DMUL`` near mid-range so the clock can be trimmed in both directions.
* Each control period, compute the fractional offset needed to drive the render-time error toward zero (typically with a slow proportional-integral loop, well below the audio bandwidth), and pass it to ``tac5112_trim_pll()`` in parts-per-billion.
  The correction is applied against the configured baseline every call, so pass the total offset from nominal, not an increment.
* ``tac5112_trim_pll()`` rewrites only the PLL fractional numerator ``DMUL`` (leaving ``PLL_DIS``, ``PDIV``, ``JMUL`` and the ``N``/``M`` dividers untouched), so the running clock is re-tuned without a re-lock.
  One ``DMUL`` step is approximately ``100 / JMUL`` ppm, so a larger ``JMUL`` gives finer resolution; dither between adjacent steps for finer average resolution.

Controller mode
===============

To place the codec in controller mode, clear both ``I2S_OPT_BIT_CLK_TARGET`` and ``I2S_OPT_FRAME_CLK_TARGET`` in the ``audio_codec_configure()`` I2S options.
The codec then drives both BCLK and FSYNC; mixed directions are rejected with ``-EINVAL``.

The codec derives its clocks from a reference clock (CCLK) that must be connected to its **GPIO2** pin.
Set ``mclk_freq`` in :c:struct:`audio_codec_cfg` to the CCLK frequency (256 kHz to 36.864 MHz); the driver then:

* configures GPIO2 as an input and routes it to CCLK,
* switches the primary audio serial interface to controller mode,
* programs the sample-rate code, the 48 kHz or 44.1 kHz family and the BCLK-to-FSYNC ratio (word size times channels), and
* selects the clock source: if ``mclk_freq`` is an integer multiple of the sample rate (up to 16383), CCLK synchronised with FSYNC is used and the CCLK-to-FSYNC ratio ``mclk_freq / sample rate`` is programmed explicitly; otherwise ``mclk_freq`` must be one of 12, 12.288, 13, 16, 19.2, 19.68, 24 or 24.576 MHz and the fixed-CCLK mode is used.

The sample rate must be one the codec can generate exactly: one of its 48 kHz-family rates (for example 8, 16, 24, 32, 48, 96 or 192 kHz) or the same rate scaled by 44.1/48 (for example 11.025, 14.7, 22.05, 44.1 or 88.2 kHz), to within 0.01 %.
Any other ``mclk_freq`` or sample rate returns ``-EINVAL``, rather than being generated at a nearby different rate.
The sequence follows TI application report SLAAEG6A.
Check the generated BCLK and FSYNC with a logic analyser when bringing up a new board.

Limitations
***********

The driver has the following limitations:

* Only I2C control is supported.
  The codec's SPI control interface is not implemented.
* Only MSB-first data order is supported; ``I2S_FMT_DATA_ORDER_LSB`` is rejected by ``audio_codec_configure()``.
* Audio-serial-interface controller mode drives both BCLK and FSYNC; driving only one of them is not supported.
  The reference clock must be on GPIO2, and the secondary audio serial interface is not used.
* The digital volume and mute property API addresses the two stereo channels (left and right).
  Channel enable (``input-channels`` / ``output-channels`` / ``tac5112_set_channels()``) supports up to 2 channels for I2S configurations, but the PDM extensions of the wider TAx5x1x family are out of scope.
* Only the output short-circuit and virtual-ground fault interrupts are enabled.
  The clock-error interrupt is left masked.
